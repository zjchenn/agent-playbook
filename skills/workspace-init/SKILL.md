# Workspace Init

把当前工作目录（单仓、多仓或 `git worktree` 协作目录）初始化或整理为一套**极简、实时、无过度设计**的人机协作工作区，让后续每次新开对话的 Agent 都能快速拿到准确上下文，并在工作过程中自动沉淀有价值的信息。

用中文交流，代码标识符与技术术语保留原文。用户当场提出的要求优先于本文。

## 核心原则

1. **动态状态靠命令，静态决策靠文档**：分支、`HEAD`、未提交改动等易变信息要求新对话用一行 Git 命令实时读取，不靠人工维护容易过期的静态快照。
2. **反过度设计与按需懒创建（Lazy Creation）**：**严禁预先创建未使用的空目录、空模板、辅助脚本或复杂元数据文件（如 `meta.json`、`registry.jsonl`）**。开始时只建当前真正有内容的文件，其余目录（如 `docs/`、`experiments/`）先把规则写进 `AGENTS.md`，等到实际产生内容时再创建。
3. **无损整理既有内容**：整理已有散乱文档时，消除重复和过期误导，但**不丢弃原始信息**——现行有效的提炼进主文档，已被推翻或仅作溯源的早期原始文档原样移入 `docs/archive/` 并在顶部加两行归档说明。
4. **主动沉淀，不等提醒**：在生成的 `AGENTS.md` 中明确写入自动更新触发规则，让后续 Agent 遇到关键进展、设计变更、踩坑诀窍或实验结论时主动同步文档。

---

## 执行步骤

### 1. 实地盘点（先看清现状）

先并行检查当前工作目录的真实情况，不要凭猜想动手：
- 目录与仓库结构：有哪些代码仓、`git worktree`、只读参考目录、共享虚拟环境（如 `.venvs/`）；各仓库当前分支、最近提交与未跟踪残留文件。
- Git 作者配置：检查已有 `AGENTS.md` 或仓库 `git config user.name` / `user.email`，保留用户的作者约定。
- 现有散落文档：通读根目录下已有的说明、待办、设计稿或状态文件，区分「现行有效信息」与「已过期的早期设想」。

**何时先问、何时直接做**：
- 若目录里已有多个旧文件待合并迁移、存在未跟踪脏文件需清理，或任务目标/只读边界不明确：先用简短几行列出拟整理的结构与文件去向，确认后再改动（或按用户明确指令直接执行）。
- 若是全新空白工作区且用户已交代清楚任务背景与目录角色：直接按下方标准落盘 `AGENTS.md` 与 `STATUS.md` 并汇报。

---

### 2. 标准目录与文件结构（按需裁剪）

根目录始终保持清爽，日常只留 **2 个入口文件**；其余目录按实际内容懒创建：

```text
<workspace-root>/
├── AGENTS.md                 # 【必建】AI 自动加载入口：红线 + 实时检查命令 + 自动更新规则 + 按需创建约定
├── STATUS.md                 # 【必建】人机共享主看板：目录角色、当前进度、外部依赖、待办与踩坑备忘
├── docs/                     # 【有长文档或归档需求时再建，保持扁平，少套子目录】
│   ├── architecture.md       # 长期有效：目标边界、ADR 决策、跨模块契约、参考源码索引
│   ├── <topic_or_pr>.md      # 具体子方案设计 / 讨论纪要
│   ├── changelog.md          # 里程碑变更记录（从 STATUS.md 拆出，防止主看板膨胀）
│   └── archive/              # 早期立项/旧规划原文无损归档（顶部注明仅供溯源、勿作现行依据）
└── experiments/              # 【仅当项目涉及实验时写入 AGENTS.md 规则，首次跑实验时再实际创建】
    ├── REGISTRY.md           # 实验对比总表（基线、修改点、效果与目录链接；指标列开跑时再商定）
    └── <exp_dir>/            # 每轮实验独立自包含目录（永不覆盖历史实验）
```

---

### 3. 各文件编写要点

#### `AGENTS.md`（控制在 40～70 行，高信噪比）
必须包含以下四块（按当前项目实际目录名定制，不写空话）：
1. **Git 作者与目录红线**：作者信息；明确哪些目录是主仓/开发 worktree、哪些是**严禁修改的只读参考目录**、虚拟环境在哪、分支与提交纪律。
2. **获取实时上下文（新对话必做）**：给出适配当前目录命名的一行 `git status -sb` / `git log -n 2` / `git worktree list` 检查命令，以及各文档的按需读取指引（渐进式披露，不必一次全读）。
3. **主动更新文档规则（核心）**：明确规定后续 Agent 在对话中一旦产生或发现以下信息，**在当前任务收尾时主动同步到文档，无需用户提醒**：
   - 进度与代码状态变化（新 commit、PR 状态变更、worktree 调整、上游依赖变化）→ 更新 `STATUS.md`（重要节点记入 `docs/changelog.md`）；
   - 方案决策与边界调整（敲定新设计、接口约定、推翻旧设想）→ 更新 `docs/architecture.md` 或对应方案文档；
   - 踩坑经验与环境诀窍（源码陷阱、坐标/参数易错点、依赖/权限/启动注意事项）→ 记入 `STATUS.md` 备忘节或 `docs/architecture.md`；
   - 实验结论与发现 → 同步记入当轮实验目录与 `experiments/REGISTRY.md`。
4. **反过度设计与按需创建约定**：
   - 声明只记结论、关键原因、复现命令与真坑，优先就地更新已有文件，不预建未使用的空目录与模板；
   - 若项目涉及对比实验，写明下述 **实验目录自包含规则**。

#### 对比实验规则（写入 `AGENTS.md`，首次跑实验时再建 `experiments/`）
- **`experiments/REGISTRY.md`**：一张总表记录每轮实验的对照基线、修改点、实验效果与目录链接。**初始化时不预设死板指标表头**，等实际跑第一轮实验时再与用户讨论确定具体指标列。
- **`experiments/<实验目录名>/`（单步完全自包含）**：每轮实验一个独立目录，永不覆盖历史目录，内含：
  1. `README.md`：本轮目的、相对基线的修改点（含分支/commit 或未提交改动 `code.patch`）、实验结果与结论；
  2. **本轮有调整的所有文件**（如启动/评测脚本、配置文件、Prompt 调整等）统一放在该实验目录下留档，方便随时回查（禁止只改外部公共脚本而不留快照）；
  3. 结果产物（轻量结果直接放目录内；若视频/原始日志体积很大可放外部数据目录并在 `README.md` 注明路径）。

#### `STATUS.md`（控制在 50～80 行，只放当前态）
- 包含：本地目录/Worktree 概览、任务/PR 进度表、外部依赖追踪（如有）、下一步待办（含二期候选池）、环境与权限踩坑备忘。
- 把长篇架构论证拆去 `docs/architecture.md`，把按日累积的历史流水拆去 `docs/changelog.md`，保证 `STATUS.md` 一屏可读。

---

### 4. 收尾校验

1. 核对所有新建/修改 Markdown 文件中的相对链接均真实可达，无断链。
2. 确认没有留下任何空目录、空模板文件或已迁移旧文件的残留副本。
3. 若顺手清理了代码 worktree 中的冗余未跟踪文件，复跑相关 `git status`（及必要的快速单测）确认干净无误。
4. 简明汇报整理后的文件列表与职责。
